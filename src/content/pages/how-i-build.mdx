## Architecture First

Every project starts with understanding the system before writing code. I map data flow, define boundaries, and design the architecture before choosing tools or writing implementations.

This produces systems that are easier to test, easier to maintain, easier to extend, and easier to hand off.

## Test-Driven Development

I write tests before production code. Every function, every component, every feature starts with a failing test that describes the desired behavior. The implementation is the minimum code that makes the test pass.

This is not a preference — it is a discipline that catches bugs before they exist and produces documentation through executable specifications.

## AI-Augmented Workflow

I use AI tools throughout my development process — not as a crutch, but as a force multiplier. AI-assisted code review, architecture exploration, test generation, and documentation. The result is higher quality output delivered faster.

When I build AI into products, I apply the same engineering rigor: cost control, hallucination prevention, retrieval-augmented generation, and real evaluation — not just API calls.

## Security and Performance

Security is a design principle, not a checklist. Input validation, rate limiting, secure headers, and content security policies are built into the foundation, not bolted on at the end.

Performance is a feature. Every system I build targets Lighthouse 95+ and is optimized for real-world load times, not just synthetic benchmarks.

## Collaboration

I work closely with designers and product teams. My job is to translate vision into reliable, maintainable systems — to say "yes, and here is how we make it work long-term" rather than "no, that is too hard."

The best products come from engineers and designers who respect each other's expertise and work together to find the right solution.
